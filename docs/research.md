# Primary-source checks (23 October 2026)

Fetched the following official documentation during implementation. Some original trailing-slash requests returned 403; canonical URLs or official source repositories below succeeded. These observations describe documentation, not live provider tests.

- [Paystack webhooks](https://paystack.com/docs/payments/webhooks): raw-byte HMAC SHA512 in `x-paystack-signature`, verification before processing, acknowledgement with HTTP 200. Current docs describe live retries every 3 minutes for the first 4 tries, then hourly for 72 hours; test-mode retry behavior differs. **This lab does not reproduce that infrastructure/schedule.** It sends `payment.succeeded`/`payment.pending` synthetic sample state events, not Paystack event schemas. There is no invented Paystack pending event or live payment verification.
- [Stripe webhooks](https://docs.stripe.com/webhooks): duplicate deliveries and non-guaranteed event order require deliberate handling. Stripe CLI forwards/triggers provider test events and supports local development. No Stripe signature/provider adapter is implemented here.
- [Hookdeck basics](https://hookdeck.com/docs/hookdeck-basics): inspection, retries, replay, delivery metrics and flow control already exist. This project's focus is small locally executable scenarios tied to developer-declared business outcomes and an owned worker-crash harness. No uniqueness or demand claim is established by this comparison.
- [node-postgres transaction docs source](https://github.com/brianc/node-postgres/blob/master/docs/pages/features/transactions.mdx): all transaction statements use the same checked-out client; do not mix `pool.query` statements into a transaction. Applied in ingress and worker transactions.
- [Zod official README](https://github.com/colinhacks/zod/blob/main/packages/zod/README.md): `safeParse` returns discriminated success/error data. Applied to strict config/event schemas and read-only adapter response validation.
- [Node releases](https://nodejs.org/en/about/previous-releases): Node 24 is LTS. Current machine is 24.19.0. Exact compatible package versions were resolved from npm metadata and saved in package-lock.json; no global tool installation is required.

Actual runtime capabilities: Docker daemon responds; official PostgreSQL 17 image pulled with verified content digest and reports server17.11; system Chromium is present. Native Git HTTPS read works through existing platform authentication. The initial `gh auth status` failed; later native Git push, repository API access and PR creation succeeded. A transient earlier Forbidden response did not establish missing credentials. No GitHub token was requested or extracted. Local subagent tools support real workers but offer no enforced read-only reviewer sandbox.
